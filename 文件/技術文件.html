Remote kill switch — offline-mode license revocation

# Public (no auth) — offline clients phone home here every 24h
GET  /api/revocation/list              → { updated, count, revoked: [uuid…], details: [{ id, revokedAt, reason }] }
GET  /api/revocation/check?id=<uuid>  → { id, known, revoked, revokedAt?, reason? }

# Admin (cookie-auth)
GET    /api/admin/licenses?filter=active|revoked     → list issued licenses
POST   /api/admin/licenses              { id (UUID), customer?, plan?, expires_at?, notes? }
POST   /api/admin/licenses/:id/revoke   { reason? }
DELETE /api/admin/licenses/:id/revoke   (unrevoke)
DELETE /api/admin/licenses/:id          (hard delete — test cleanup)

# Client (offline mode) — UI 上 "立刻更新撤銷清單" 按鈕
POST /api/license/revocation/refresh   → { ok, error? }

Flow：license-tools/issue-license.js 簽 .key 時生成 UUID 存進 payload 的 lid； Admin 在 License Server 註冊（手動或 import-licenses），之後可隨時 revoke。 Client (Node + .NET) 每 24h 取 /list，cache 到 .revocation-cache.json，命中 → status revoked → gate 回 403。 30 天 grace 期：拿不到清單超過 30 天就視為 expired（避免拔網路繞過）。 舊版 v1 license（沒 lid）向下相容、不做檢查。

License Server — DB Schema

CREATE TABLE users (
  id                     TEXT PRIMARY KEY,
  email                  TEXT UNIQUE NOT NULL,
  password_hash          TEXT NOT NULL,            -- bcrypt 10 rounds
  plan                   TEXT NOT NULL DEFAULT 'trial',
  max_devices            INTEGER NOT NULL DEFAULT 1,
  trial_started_at       DATETIME,
  expires_at             DATETIME,                 -- paid plan expiry
  is_admin               INTEGER NOT NULL DEFAULT 0,
  email_verified         INTEGER NOT NULL DEFAULT 0,
  email_verify_token     TEXT,
  ip_whitelist           TEXT,                     -- JSON array of CIDRs
  free_until             DATETIME,                 -- "this month free" override
  stripe_customer_id     TEXT,
  notes                  TEXT,                     -- admin internal notes
  created_at             DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE sessions (
  id                     TEXT PRIMARY KEY,         -- the bearer token
  user_id                TEXT NOT NULL,
  ip                     TEXT NOT NULL,
  user_agent             TEXT,
  created_at             DATETIME DEFAULT CURRENT_TIMESTAMP,
  last_seen              DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE TABLE event_log (
  id                     INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id                TEXT,
  ip                     TEXT,
  user_agent             TEXT,
  event                  TEXT NOT NULL,
    -- 'register' / 'email_verified' / 'login' / 'login_blocked'
    -- / 'kicked' / 'expired' / 'logout' / 'plan_upgraded' / ...
  details                TEXT,                     -- JSON
  at                     DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE admin_sessions (
  id                     TEXT PRIMARY KEY,         -- cookie value
  user_id                TEXT NOT NULL,
  ip                     TEXT,
  created_at             DATETIME DEFAULT CURRENT_TIMESTAMP,
  last_seen              DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE issued_licenses (                  -- offline-mode kill switch
  id                     TEXT PRIMARY KEY,         -- UUID from license-tools (= payload.lid)
  customer               TEXT,
  plan                   TEXT,
  issued_at              DATETIME DEFAULT CURRENT_TIMESTAMP,
  expires_at             DATETIME,
  revoked_at             DATETIME,                 -- NULL = active; set = revoked, will appear in /revocation/list
  revoke_reason          TEXT,
  source                 TEXT DEFAULT 'manual',    -- manual | cli | import
  notes                  TEXT
);
CREATE INDEX idx_licenses_revoked ON issued_licenses(revoked_at);

Migration 策略：db.js 啟動時呼叫 addColumnIfMissing()，新版 schema 改動不會弄壞舊 DB。

License Key 格式（offline 模式）

JWT-like：<base64url-payload>.<base64url-Ed25519-sig>

// payload v2 (decode base64url 後) — 新發行 license 從 v2 開始都有 lid
{
  "lid":     "c3a4e1d8-91f7-4b21-8c0e-2e3a9d6f7b54",   // UUID — 用於遠端撤銷
  "rurl":    "https://license.example.com/api/revocation/list",  // 可選，可被 LICENSE_REVOCATION_URL env 覆蓋
  "customer": "Acme Inc",
  "plan": "team",
  "users": 5,
  "issued":  "2026-05-15T00:00:00.000Z",
  "expires": "2027-05-15T23:59:59.000Z",
  "v": 2
}

// signature
Ed25519(privateKey, base64url(payload))

// 驗證（client 端）
Ed25519.verify(publicKey, base64url(payload), sig) === true
   AND payload.expires > now
   AND (payload.lid IS NULL OR revocation_cache.check(payload.lid) ≠ 'revoked')   // v2+

// 向下相容：v1 license（沒 lid）依舊有效，但無法被遠端撤銷

公鑰嵌在 client（安全發佈），私鑰只在 owner 機器上用 license-tools/ 來簽。 v2 開始 client 會額外維護 .revocation-cache.json：每 24h fetch rurl 一次，命中即拒絕啟動；30 天拿不到清單則強制 expired（防拔網路繞過）。

Plugin Marketplace — Manifest 格式

每個可上架的 plugin 在 repo root 放一份 plugin.json。Client 從 raw.githubusercontent.com/<owner>/<repo>/<ref>/plugin.json 抓下來驗章。

{
  "name":        "hello-plugin",        // slug：alnum / _ / -，≤ 64 chars
  "version":     "1.0.0",
  "description": "Demo plugin",
  "author":      "Your Name",
  "files": {
    "node-express": ["index.js", "src/helper.js"],
    "dotnet8":      ["Hello.cs"],
    "shared":       ["LICENSE"]         // 同時複製到兩個 runtime
  },
  "hashes": {                            // 由 sign-plugin.js 自動填
    "node-express": { "index.js": "<sha256-hex>", "src/helper.js": "<sha256-hex>" },
    "dotnet8":      { "Hello.cs":  "<sha256-hex>" },
    "shared":       { "LICENSE":   "<sha256-hex>" }
  },
  "signedAt":    "2026-05-17T10:00:00.000Z",
  "signature":   "<base64 Ed25519 sig over canonical-JSON(manifest with signature='')>"
}

Canonical JSON：對所有 object 把 key 用 codepoint 排序、無空白、recursively。Node 與 .NET 兩邊用相同實作（marketplace.js / MarketplaceService.cs）。

簽 plugin

# 你自己 plugin 開發者：
node license-tools/sign-plugin.js /path/to/your/plugin-dir
# → 自動算 SHA-256 → 寫進 hashes → 用 license-tools/private-key.pem 簽 → 印 signature

Client 驗證流程

  1. URL gate：拒絕非 github.com URL
  2. Manifest validate：name slug、files 結構、每條 file path 通過 isSafeRelativePath（不能 absolute / drive letter / .. / 怪字元）
  3. Hash verify：抓每個檔案 → SHA-256 → 跟 manifest.hashes 對比
  4. Signature verify：對 trusted-publishers.json（預設含 license-tools/public-key.pem）所有 PEM 嘗試 Ed25519 verify；命中 → trusted；否則 untrusted（UI 強制 user 勾選確認框）
  5. Atomic install：寫到 plugins/<name>.staging-<ts>/ → isInside() 雙重檢查每個輸出檔 → renameSync 到 plugins/<name>/（pluginHost 自動 hot reload）

Dump 格式 — Routine marker

SQL adapter 的 procedure / function / trigger / event body 包 BEGIN ... END 區塊，內部有 ;。樸素的 SQL splitter（split on ; outside literals）會把這些當分隔符切壞。 解法：在 dump 時用標記把整個 routine 包起來：

-- ROUTINE_BEGIN procedure add_user
CREATE PROCEDURE add_user(IN name VARCHAR(64))
BEGIN
  INSERT INTO users(name) VALUES (name);
  SELECT LAST_INSERT_ID();
END
-- ROUTINE_END

Restore 端 extractRoutineBlocks() 走過 dump，產生 [{kind:'sql',body}, {kind:'routine',body}, ...]。SQL 區塊照舊跑 splitter，routine 區塊整段送 driver（無 split）。

各 adapter 套用對象：

  • MySQL：triggers、procedures、functions、events 全包
  • PostgreSQL：functions、procedures 包；sequences / views 不用（無內部 ;）；triggers 用 pg_get_triggerdef 出來的單行 SQL
  • SQL Server：不用 marker — 改用 GO batch separator（既有 restore 已支援）
  • SQLite：不用 marker — schema 內無 procedure / function 概念

實作：[node-express/adapters/_shared.js](../node-express/adapters/_shared.js) extractRoutineBlocks；[dotnet8/Adapters/SqlHelpers.cs](../dotnet8/Adapters/SqlHelpers.cs) ExtractRoutineBlocks。兩邊行為 byte-compatible。

Dump 格式 — NoSQL adapter

SQL adapter 的 dump 就是「能直接被自己 driver 跑」的 SQL，所以格式不需要文件化。NoSQL 兩個 adapter 用自家格式：

MongoDB — JSONL / EJSON canonical

// 每行一個 JSON event，EJSON canonical 保留 BSON 型別
{"op":"header","adapter":"mongo","db":"mydb","generated":"2026-05-17T...","collections":["users","posts"]}
{"op":"collection","name":"users","options":{},"indexes":[{"key":{"email":1},"name":"email_1","unique":true}]}
{"op":"insert","coll":"users","doc":{"_id":{"$oid":"..."},"email":"a@b.c","createdAt":{"$date":"..."}}}
{"op":"insert","coll":"users","doc":{"_id":{"$oid":"..."},"email":"d@e.f"}}
{"op":"collection","name":"posts","options":{},"indexes":[]}
{"op":"insert","coll":"posts","doc":{"_id":{"$oid":"..."}}}

Restore：對每個 collection event 先 drop 再 createCollection + createIndexes；insert events 用 1000 個一批的 insertMany(ordered=false)。重複 _id 會 soft-warn 不會中斷。

Redis — redis-cli 風格 command 序列

# DB Migrator dump (Redis db=0)
SELECT 0

SET user:1 "Alice"
HSET user:2 name "Bob" age "30"
SADD session:abc "x" "y" "z"
ZADD scoreboard 99.5 alice 88 bob
RPUSH queue "task1" "task2"
PEXPIRE user:1 3600000

Restore 逐行 db.call(cmd, ...args)，失敗 soft-warn 不中斷。Tokenize 規則跟 redis-cli 一樣：bareword 不 quote、含空白或 "/\ 才 double-quote + escape。

列表單位 ("tables")：Mongo 是 collection；Redis 是 namespace ＝ key 第一個 : 前的字串 + :*（無前綴的 key 都歸到 _root）。 Import 過濾用各 adapter 自己實作的 filterDumpByTables；SQL 系列 fallback 到共用的 filterSqlByTables(text, tables, quoteChar)。

安全模型

密碼

  • License server：bcrypt 10 rounds
  • DB Migrator 內存的目標 DB 密碼：明文（直接傳給 driver；不持久化在 server）
  • Browser localStorage 存的「最近使用」連線：明文（per-browser only）

Token / Session

  • License server session token：32-byte 隨機 hex（256 bit），單一 active per user × max_devices
  • Admin session cookie：32-byte 隨機 hex，HttpOnly + Secure (HTTPS) + SameSite=Lax
  • Token 被 IP 變更或被踢時 server 端立即刪除，client 下次 heartbeat 收到 401

傳輸

  • License server 必須 部署於 HTTPS，否則密碼會明文傳輸
  • 使用 reverse proxy（nginx / Caddy）終結 TLS，server 本身只跑 HTTP
  • app.set('trust proxy', true) 已啟用，正確讀取 X-Forwarded-For

注入 / XSS

  • 所有 SQL 操作走 driver parameterized query（DB Migrator 內部）
  • Admin web UI 的所有使用者輸入都經 escape 後再 render
  • License server 沒有用到 shell — 無 command injection

Rate limit

  • /api/auth/register、/api/auth/login、/api/auth/verify-email：5 min 窗口、20 req/IP
  • 更激烈的暴力測試應在 nginx / Cloudflare 那層擋

已知限制

  • Offline mode：人能拿原始碼把 license 檢查 patch 掉，這只能靠法律 + license key 機制嚇阻
  • 沒有 2FA、沒有 password reset email（只有 admin 手動改）
  • 事件 log 沒做 retention 清理 — 跑久會爆，建議每月手動 vacuum

測試策略

層位置覆蓋什麼跑法
Unit node-express/test/ (87 個)
license-server/test/ (55 個)		 純函式：SQL splitter / Mongo EJSON parse / Redis quote / canonical JSON / IP wildcard / TOTP / ECPay MAC / revocation cache / plugin manifest 驗章 npm test（秒級，無外部依賴）
Integration integration/ 真實 driver × adapter 組合：mysql 8.4 / postgres 16 / mssql 2022 / mongo 7 / redis 7（sqlite 本機檔）；每 adapter 跑 seed → dump → parseTableNamesFromDump → drop → restore → verify counts cd integration && npm run up && npm test && npm run down（需 Docker；約 3 分鐘）
CI .github/workflows/ ci.yml 跑 unit（matrix: ubuntu/windows × Node 18/20）；integration.yml path-filtered，只在 adapter / integration 變動時觸發 自動 — push 到 main / PR

為什麼分兩層：unit 跑得快、隨時跑；integration 抓「driver 行為 × adapter SQL 形狀」邊角 case（例：MSSQL bracket `[users]` 在 extractTableName regex 上的解析、Mongo EJSON 在 Node 與 .NET 端的 byte-compatibility）。Integration 失敗時上傳 dumps + container logs 當 artifact，便於 debug。
