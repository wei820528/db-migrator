R-01　License 三模式統一介面 P0

問題

現在 Node 端用 lib/license.js 包了 offline 跟 online 兩個子模組，但 .NET 端只有 offline。三邊（offline / online / disabled）的 API surface 不完全一致，前端也要自己 if/else。

建議

  • 定義一個統一的 LicenseProvider 介面：getStatus() / login(...) / logout() / saveKey(...) / removeKey()
  • 三個實作：OfflineProvider、OnlineProvider、NoopProvider（disabled）
  • 主程式只跟介面對話 → 模式切換靠 DI / factory
  • 對應到 .NET：ILicenseProvider + OfflineLicenseProvider 等三個 class

影響範圍

  • Node：lib/license.js + lib/license-online.js + lib/license-offline.js 重構
  • .NET：Services/LicenseService.cs 拆分 + 加 LicenseOnlineProvider.cs
  • API gate middleware 不動

R-02　.NET online client 整合 P0

問題

.NET 後端目前沒接 license server，LICENSE_MODE=online 切過去後 /api/license/online/login 等 endpoint 不存在會 404。

建議

  1. 新增 Services/LicenseOnlineService.cs，邏輯對應 Node 的 lib/license-online.js（HttpClient 呼叫 license server，token 存於 .auth-token，每 30 秒 heartbeat）
  2. Controller 加 POST /api/license/online/login、register、logout
  3. Program.cs 的 license gate middleware 多 mode 判斷 + feature gate
  4. 環境變數：LICENSE_MODE / LICENSE_SERVER_URL

注意

protocol 跟 license server 已定型，照 Node 版翻譯即可。預估 2 小時。

Job 資料持久化 P1

問題

目前 job 狀態存在記憶體（Node：Map / .NET：ConcurrentDictionary），server 一重啟所有 job 進度就消失。客戶在跑 30 分鐘的大匯出，server 重開就斷掉看不到結果。

建議

  • Job 改存於本機 SQLite
  • 啟動時 load 未完成的 job → 標記為 error: server restarted
  • tmp 檔案路徑也存進去 → 重啟後可以繼續提供下載連結

更激進的做法

Job 改成 worker pattern（背景 process），server 只負責 enqueue + 查狀態。但目前用量沒到那個程度，先 SQLite 持久化就夠。

tmp 自動清理 P1

問題

tmp/<jobId>/ 沒人清，跑久了會塞滿磁碟。匯出 / 上傳檔案都堆在那。

建議

// 啟動時 + 每 6 小時跑一次
function cleanupTmp() {
  const cutoff = Date.now() - 24 * 60 * 60 * 1000;  // 24h
  for (const dir of fs.readdirSync(TMP_DIR)) {
    const full = path.join(TMP_DIR, dir);
    const stat = fs.statSync(full);
    if (stat.mtimeMs < cutoff) fs.rmSync(full, { recursive: true, force: true });
  }
}

job 完成後可以呼叫 callback 立即清；timeout 是兜底。

用 ES modules（type="module"），各 module 自帶 setup function。

Adapter 介面型別化 P2

問題

Node 版 adapter 介面靠 convention（每個 module export 5 個函式），沒有編譯期保證。寫 plugin adapter 漏實作會 runtime 噴錯。

選項

  • (A) 加 .d.ts 型別宣告，讓 IDE 提示 — 不影響 runtime
  • (B) 整個 Node 端轉 TypeScript — 影響大，但長期收益高
  • (C) 加 runtime validator：adapters/index.js 註冊時呼叫 validateAdapter() 確認 5 個方法都有

建議先做 C（成本低、立即見效），TypeScript 化等專案再大些再說。

移除前後端密碼明文存放 P2

問題

  • 瀏覽器 localStorage 存「最近使用」的 DB 密碼明文
  • License server 從 client 收到的 DB 連線資訊（轉發給 adapter）也明文 in-memory

建議

  • localStorage：用 SubtleCrypto + 一個 device-bound key 加密儲存（或乾脆「不存密碼」+ 每次手填）
  • 記憶體中：可加 SecureString 包裝 — 但 JS 沒這玩意，能做的有限
  • 最實際的：在 UI 加開關「儲存密碼」預設關

統一錯誤格式 + i18n P2

問題

各 endpoint 的錯誤回傳格式不統一：

  • { error: "..." }
  • { ok: false, error: "..." }
  • { error, license: {...} }
  • ASP.NET ProblemDetails ({ title, status, errors })

建議

// 統一格式
{
  "error": {
    "code": "TRIAL_EXPIRED",   // 機器可讀
    "message": "您的試用期已結束",  // i18n key
    "feature": "bulk_export",   // 額外 metadata
    "license": { ... }
  }
}

前端用 error.code 切錯誤訊息（中/英文翻譯表）。

事件 log retention 自動化 P3

問題

event_log 表只增不刪。一年後會很大。

建議

// 每天午夜
db.prepare("DELETE FROM event_log WHERE at < date('now', '-90 days')").run();
db.prepare("VACUUM").run();

或更彈性：把 retention 天數放 env var EVENT_RETENTION_DAYS=180。
