整體擴充模型

DB Migrator 故意分了幾種擴充強度，挑你需要的最弱那個就好（弱 = 影響範圍小、出錯不會弄爆別的）：

強度方式需要重啟嗎影響範圍
1. 設定檔修 plans.js / env vars是（license-server）該 server
2. Plugin (legacy)丟 .js 進 plugins/否 (hot reload)整個 process，full Node access
3. Plugin (sandboxed)plugin.json + sandboxed:true否worker_thread，crash 隔離
4. Plugin marketplaceGitHub repo + sign-plugin.js 簽否使用者裝才生效
5. Fork repogit fork + 改 source是無上限

絕大多數新功能用 plugin (sandboxed) 就夠了；要加新 DB type 才需要碰 adapter（fork 或 plugin 的 adapter capability）。

1. 新增 DB Adapter（支援新的 DB 類型）

位置

  • Node 版：node-express/adapters/<type>.js，註冊在 adapters/index.js
  • .NET 版：dotnet8/Adapters/<Type>Adapter.cs，註冊在 Adapters/IDatabaseAdapter.cs 的 AdapterRegistry

契約（必須實作的方法）

// node-express/adapters/<name>.js
module.exports = {
  type: 'myhouse-db',
  async testConnection(conn)         { return { ok, version, databases? }; },
  async listTables(conn)             { return [{ name, rowEstimate }]; },
  async dump(conn, opts, out, onProg){ /* 寫 SQL/JSONL 進 out 檔 */ },
  async restore(conn, file, onProg)  { /* 讀檔還原 */ },
  parseTableNamesFromDump(file)      { return ['table1', 'table2']; },

  // 可選：自家 dump 格式時的篩選邏輯（不實作就 fallback 到 SQL splitter）
  filterDumpByTables(text, wanted)   { return { sql, kept, skipped }; },

  // 可選：v2 Theme B 跨 DB migration 才需要
  async getSchema(conn, tables?)     { return [{ name, columns: [...IR...] }]; },
  async dumpNeutral(conn, opts, out, onProg)    { /* 寫 neutral JSONL */ },
  async restoreNeutral(conn, file, onProg)      { /* 讀 neutral 還原 */ },
};

註冊

編輯 adapters/index.js 的 loaders 物件加一行：

const loaders = {
  mysql:    () => require('./mysql'),
  ...,
  'myhouse-db': () => require('./myhouse-db'),    // ← 加這個
};

UI 端

編輯 public/index.html 加一張 <button class="card" data-type="myhouse-db">；編輯 public/modules/state.js 在 HOST_HINTS 跟 TYPE_DEFAULTS 加 entry。或者透過 plugin 的 ui.cards 動態注入，連 HTML 都不用改。

已實作的 adapter 可當範本

  • SQL 系：mysql / postgres / mssql / sqlite
  • NoSQL：mongo / redis（要實作 filterDumpByTables，因為 dump 不是 SQL 字串）
  • 別名：supabase 直接重用 postgres adapter

2. Plugin — Legacy in-process（最快、最不安全）

位置

丟 node-express/plugins/<name>/index.js（或單檔 plugins/<name>.js），自動 hot reload。.NET 版是 dotnet8/Plugins/<Name>.cs，重建生效。

契約

// 一個 plugin 可同時 export 任何組合：
module.exports = {
  mount:  '/api/foo',
  router: require('express').Router().get('/', (req, res) => res.json({ok: true})),
  adapter: { type: 'foo-db', handler: { testConnection, listTables, ... } },
  ui: {
    cards: [{ type: 'foo-db', title: 'Foo DB', sub: 'demo', port: '0' }],
    tabs:  [{ id: 'foo-tab', label: 'Foo Tools', html: '...', scripts: ['/plugins/static/foo/x.js'] }],
    scripts: ['/plugins/static/foo/init.js'],
  },
  static: 'public',  // 服務 plugins/foo/public/* 在 /plugins/static/foo/*
};

注意

  • 完整 Node.js 存取 — 可以 require('fs') 為所欲為。只給可信來源寫的 plugin 用
  • 跟主 process 共享 event loop — plugin while(true){} 會卡死整個 server
  • Plugin throw 沒抓會 take down main server
  • 適合 dev / 自己內部的小工具；對外發佈請用下方 sandboxed 模式

範本：[plugins/hello/index.js](../node-express/plugins/hello/index.js)

3. Plugin — Sandboxed worker_thread（v2 Theme D Phase 2+3）

觸發方式

Plugin 資料夾內放 plugin.json，含 "sandboxed": true。pluginHost 會走 worker_thread 路徑載入。

契約變更

跟 legacy 不一樣：plugin 必須 export 一個 function(ctx)，不是 object。Plugin 對外唯一通道是 ctx 物件。

// plugins/<name>/index.js
module.exports = function (ctx) {
  ctx.log('booted');

  ctx.route.mount('GET', '/', async (req) => {
    return { status: 200, body: { ok: true, params: req.params } };
  });
  // path 支援 :named param，handler 拿到 req.params

  ctx.route.mount('POST', '/echo/:id', async (req) => {
    return { status: 200, headers: { 'X-Custom': 'yes' }, body: req.body };
  });
};

ctx 物件目前內容

欄位用途
ctx.pluginName自己的名字
ctx.permissionsgranted permission 陣列
ctx.threadIdworker thread id（debug 用）
ctx.log(...) / .debug() / .info() / .warn() / .error()跨 thread 印到 main console
ctx.route.mount(method, path, handler)註冊 endpoint（要 route permission）
ctx.hasPermission(p)檢查自己有沒有某個 perm

require() 受 gate 控制（v2 Theme D Phase 3）

Plugin 自家檔案的 require() 會被 plugin-worker.js 攔 — 按 granted permissions 過濾：

  • 永遠通：crypto / util / events / stream / buffer / url / path / querystring / assert / timers / string_decoder
  • fs:tmp 或 fs:plugin-dir → 解鎖 fs, fs/promises
  • network → 解鎖 http, https, http2, net, dns, tls, dgram
  • unrestricted → 全開（legacy escape hatch）
  • 絕對禁（除非 unrestricted）：child_process, vm, cluster, os, worker_threads

npm packages（非 builtin）跟 relative require（./helper）一律通；npm package 內部的 require 也通（不然依賴會炸）。

限制

  • Phase 2/3 只支援 route — adapter / UI / static 還不能在 sandbox 用，要走 legacy 路徑
  • 單一 request timeout 30s
  • Worker startup timeout 10s
  • 仍未擋：process.dlopen、SharedArrayBuffer + Atomics、new Worker(code,{eval:true}) 子 worker

範本：[plugins/sandboxed-hello/](../node-express/plugins/sandboxed-hello/) 含 /try-fs demo 看 gate 動作。

4. Plugin marketplace 發佈（讓別人從 GitHub 一鍵裝你的 plugin）

流程

  1. 寫 plugin（legacy 或 sandboxed）跟 plugin.json
  2. 用 node license-tools/sign-plugin.js <plugin-dir> 簽 — 自動算 SHA-256 + 用 license-tools 的 Ed25519 私鑰簽 manifest
  3. Push 到 GitHub repo（public 或 private 都行，要能 raw 讀取）
  4. 使用者在 UI「外掛商店」tab 貼 https://github.com/<you>/<repo> → 預覽（含 SHA / 簽章 / permissions）→ 勾權限 → 安裝

plugin.json 完整 schema

{
  "name":        "my-plugin",         // slug
  "version":     "1.0.0",
  "description": "...",
  "author":      "...",
  "sandboxed":   true,                 // 可選；true 則必須 export function(ctx)
  "mount":       "/api/plugin/my-plugin", // 可選，sandboxed plugin 用
  "files": {
    "node-express": ["index.js", "src/helper.js"],
    "dotnet8":      ["MyPlugin.cs"],     // 可選
    "shared":       ["LICENSE"]          // 可選
  },
  "permissions": ["route", "ui:cards"],  // 11 種可選 - 見 §9
  "hashes":      { ... },                // 由 sign-plugin.js 自動填
  "signedAt":    "...",
  "signature":   "..."                   // base64 Ed25519
}

信任 publisher

使用者預設只信任你 repo 內 license-tools/public-key.pem 那把（project-default）。要信任別人的 plugin publisher，admin 在 UI 加 PEM 到 node-express/trusted-publishers.json。未簽章 plugin 安裝時必須勾「我已檢查過原始碼」確認框。

5. Cross-DB migration 加新方言（v2 Theme B）

目前支援 MySQL ↔ PostgreSQL ↔ SQLite 三角共 6 個方向。要加新方言（例如 MSSQL）需要：

必改的檔

  1. [normalize.js](../node-express/lib/cross-db/normalize.js) — 加 normalizeMssql(src) 把 MSSQL 型別字串 → IR object
  2. [emit.js](../node-express/lib/cross-db/emit.js) — 加 emitMssql(ir) 把 IR → MSSQL DDL fragment（含 lossy warning）
  3. [tables.js](../node-express/lib/cross-db/tables.js) — normalizeTarget() + buildColumnDdl() 加 mssql case（autoIncrement / NOT NULL 規則）
  4. Adapter 端（mssql.js）加 getSchema + dumpNeutral + restoreNeutral
  5. Test：複製 cross-db.test.js 的 normalize / emit 區段，補 mssql
  6. Integration：integration/run-crossdb.js 把 mssql 加進 SUPPORTED 陣列

IR 已知 kind

int / float / decimal / string / text / binary / bool / date / datetime / time / json / uuid / enum / unknown。如果你的方言有特殊型別（PG 的 inet / mac / tsvector），先 normalize 成 unknown + warning 即可。

6. License 模式

三種 mode 透過 LICENSE_MODE env 切：

  • offline（預設）— Ed25519 簽章的 license.key 檔 + .trial 計時。32 天試用。實作在 [lib/license-offline.js](../node-express/lib/license-offline.js)
  • online — heartbeat 到 license-server，IP 換了會被踢，feature gate 跟 plan 走。7 天試用。實作在 [lib/license-online.js](../node-express/lib/license-online.js)
  • disabled — gate 完全關掉（dev only，會印警告）

要加新 mode（例如 jwt）只要在 [lib/license.js](../node-express/lib/license.js) 的 mode dispatcher 加一支，回相同 shape：

function getStatus() {
  if (MODE === 'jwt') return { status, daysLeft, info, features, mode: 'jwt' };
  ...
}

Gate 行為（哪些 endpoints 要授權才能用）在同檔的 gate() middleware。新 endpoint 預設都 gated；要 expose 給 unauthed 用（例如 /openapi.json）就放在 license gate 之前 註冊。

7. Webhook events

目前 5 種 + ping：job.done / job.failed / schedule.run.ok / schedule.run.failed / license.expired。

加新 event

  1. 編 [lib/webhooks.js](../node-express/lib/webhooks.js) 的 KNOWN_EVENTS 陣列
  2. 在事件發生處 call require('./webhooks').emit(eventName, payload)（fire-and-forget）
  3. Webhook payload schema：{ event, deliveryId, occurred_at, data: payload }

範例 — 加 plugin.installed

// lib/webhooks.js
const KNOWN_EVENTS = [..., 'plugin.installed'];

// lib/marketplace.js install() 完成處
require('./webhooks').emit('plugin.installed', { name, version, signed });

Receiver 端驗章方式直接寫進 OpenAPI /api/webhooks/{id} 的 description；HMAC-SHA256，header X-DBMigrator-Signature: sha256=<hex>。

8. API token scopes (license-server)

目前兩種：user:read, user:write。Token 是 dbmt_<random> 格式，給 cron / CI / scripts 認證用。

加新 scope

  1. 編 [license-server/lib/tokens.js](../license-server/lib/tokens.js) 的 KNOWN_SCOPES Set
  2. 在要保護的 endpoint 加 requireScope('admin:read') middleware（已在 [routes/user.js](../license-server/routes/user.js) 實作）
  3. Portal UI 的建立 token form 加新 checkbox（[public/portal.html](../license-server/public/portal.html) 跟 [portal.js](../license-server/public/portal.js)）

常見要加的 scope

  • admin:read — 列 users / sessions（給 dashboard）
  • admin:write — 改 user plan / kick session（給 ops tool）
  • billing:read — 看 invoices（給 accountant）

9. Plugin permission（v2 Theme D Phase 1）

11 種已知 permission，每個有 label / description / risk (1-3)。完整列表在 [lib/plugin-permissions.js](../node-express/lib/plugin-permissions.js) 的 PERMISSIONS 物件。

加新 permission

  1. 編 PERMISSIONS 物件加一個 key（id 用 namespace:action 格式，例 queue:publish）
  2. 編 [license-tools/sign-plugin.js](../license-tools/sign-plugin.js) 的 KNOWN_PERMISSIONS Set 同步
  3. 實際 runtime enforcement 在哪：
    • Builtin require gate — 加進 [plugin-worker.js](../node-express/lib/plugin-worker.js) 的 PERMISSION_BUILTINS 對照表
    • SDK 函式 — 在 buildCtx() 內檢查 grantedPermissions.includes(...)
    • Pre-install 檢查 — 已自動進 marketplace 的 consent UI（risk 顏色由 risk 欄決定）

Risk 標準

Risk意義UI 顏色
1純功能延伸，無資料 / 安全風險（route / ui:cards / static）綠
2可讀使用者資料但不能寫 / 對外（db:read / fs:tmp）黃
3可寫資料 / 對外網路 / 完整存取（db:write / network / unrestricted / adapter）紅

10. CLI subcommand

目前 8 個：test / list-dbs / list-tables / export / import / dump-neutral / restore-neutral / preview-crossdb。位置在 [cli/commands/](../cli/commands/)。

加新 subcommand（範例：dbmigrator schedule list）

  1. 新建 cli/commands/schedule.js：
// cli/commands/schedule.js
const path = require('path');
const { parseConnArgs } = require('../lib/conn');

exports.help = `dbmigrator schedule list  / add  / remove  ...`;

exports.run = async (subArgs) => {
  const { values, positionals } = parseConnArgs(subArgs, {
    server: { type: 'string' },   // 額外 flag
  });
  // 你的邏輯
  console.log('list of schedules...');
  return 0;
};
  1. 編 [cli/bin/dbmigrator.js](../cli/bin/dbmigrator.js) 的 COMMANDS 物件加 entry：'schedule': require('../commands/schedule')
  2. 更新頂層 help 字串（同檔下方 printHelp()）
  3. 寫 test：cli/test/dispatch.test.js 已經自動驗每個 cmd 都會回 help；conn / arg parsing 邏輯在 conn.test.js

共用 connection flags

parseConnArgs(subArgs, extraOptions) 自動處理 --type, --host, --port, --user, --password / --password-env, --database, --path, --ssl, --config <file.json>, --json, --quiet。

11. GitHub Action inputs

[action.yml](../action.yml) 是 composite action 入口，~25 個 input（連線 / 命令 / 開關）。[cli/lib/github-action.js](../cli/lib/github-action.js) 把 INPUT_* env 翻譯成 CLI args。

加新 input（範例：--region us-west-2 for S3 backup）

  1. 編 action.yml 在 inputs: 段加 region: { description: ..., required: false }
  2. 編 [cli/lib/github-action.js](../cli/lib/github-action.js)：
    • 加到 PER_CMD_FLAGS 陣列：['--region', 'region']
    • 或加 boolean: BOOL_FLAGS
    • 或如果是 source-* 用：CROSSDB_FLAGS
  3. 密碼類用 env: { DBMIGRATOR_GHA_X_TOKEN: ${{ inputs.x-token }} } + CLI 端對應 --x-token-env DBMIGRATOR_GHA_X_TOKEN，**永遠不要**直接放 args（會落到 process list）
  4. 編 [cli/test/github-action.test.js](../cli/test/github-action.test.js) — 最後一個測試會自動掃 action.yml 確認你新加的 input 有宣告

12. 付款 provider (license-server)

目前 2 種：Stripe (信用卡 / 訂閱) 跟 ECPay 綠界（信用卡 / ATM / 超商）。位置：

  • Stripe：[routes/stripe.js](../license-server/routes/stripe.js)（checkout + webhook，webhook 用 raw body 驗 signature）
  • ECPay：[routes/billing-ecpay.js](../license-server/routes/billing-ecpay.js) + [lib/ecpay.js](../license-server/lib/ecpay.js)（CheckMacValue SHA256）

加新 provider（例：PayPal）

  1. 新建 routes/billing-paypal.js 跟 lib/paypal.js
  2. 編 [plans.js](../license-server/plans.js) 加 paypal_plan_id 欄位
  3. 編 [server.js](../license-server/server.js) 在 express.json() 之前 mount（若 webhook 需要 raw body）
  4. 編 Portal UI 加付款按鈕（[portal.html](../license-server/public/portal.html) + [portal.js](../license-server/public/portal.js) 既有的 Stripe / ECPay 按鈕當範本）
  5. 付款成功一律 call db.prepare('UPDATE users SET plan = ?, expires_at = ? WHERE id = ?') + event_log 進一筆 plan_upgraded event

13. OpenAPI tag / endpoint

兩份 spec：[node-express/openapi.json](../node-express/openapi.json)（10 個 tag）跟 [license-server/openapi.json](../license-server/openapi.json)（7 個 tag）。Swagger UI 在 /api-docs/（兩個 server 都有）。

加新 endpoint 後要做的

  1. 在 paths 段加 "/api/foo": { "post": { tags, summary, requestBody, responses } }
  2. 確認 tag 在 tags 陣列裡有定義（沒有就加）
  3. 用到的 schema 抽出來放 components.schemas（之後別的 endpoint 也能引用）
  4. 跑 npm test --prefix node-express -- test/openapi.test.js，會自動驗：
    • 每個 op 有 tags + summary + responses
    • 每個 path 在 server.js 都有實際 mount（catch「寫了 spec 但忘了實作」漂移）

不要加在 spec 裡的 endpoint

內部 only / debug only / 不穩定的 endpoint 可以不加 spec — 但記得在 code 註解標 // not in openapi.json — internal，免得未來人以為漏掉了。

14. UI tab / mode-switch 加項目

主 UI 有 mode-switch（匯出 / 匯入 / 專案備份 / 排程 / 外掛商店 / 跨 DB 遷移 / Webhooks）。要加新 tab：

三個地方要動

  1. [index.html](../node-express/public/index.html)：
    • mode-switch <div> 加 <button data-mode="foo">Foo</button>
    • 同檔加 <section id="step-foo" class="step mode-panel" hidden>...</section>
  2. 新建 [public/modules/foo.js](../node-express/public/modules/)：用 IIFE pattern 包，attach 到 window.DBM.foo，export init()
  3. 編 [public/index.html](../node-express/public/index.html) 的 <script> 段加 <script src="modules/foo.js"></script>；編 [public/app.js](../node-express/public/app.js) 加 D.foo.init();

如果你的 tab 是給 plugin 動態貢獻的

用 plugin 的 ui.tabs: [{ id, label, html, scripts }] 機制，不必改主 UI。plugin-ui.js 會自動掛進去。

擴充點摘要表

想做的事 最少要改幾個檔 需要 fork？
支援新 DB type（私有，自己用）1 個 adapter 檔 + index.js 註冊否（fork 或 plugin adapter）
支援新 DB type（公開，給別人用）同上 + UI 卡片 + state.js defaults是（PR 比較好）
加個內部 tool 給自己 team 用1 個 plugin .js（legacy）否
發佈 plugin 給別人裝plugin.json + sign-plugin.js + GitHub repo否
讓 plugin 在 sandbox 跑plugin.json 加 sandboxed: true + 改成 function(ctx) export否
加新付款方式1 個 route + 1 個 lib + plan.js 加 price ID + Portal UI 按鈕是
加新 webhook 事件KNOWN_EVENTS 陣列 + emit() 一行是
加新 API token scopeKNOWN_SCOPES + Portal checkbox + requireScope middleware是
加新 plugin permissionPERMISSIONS 物件 + sign-plugin 的 KNOWN_PERMISSIONS + runtime gate是
加新 CLI subcommand1 個 cli/commands/<name>.js + COMMANDS 註冊否（cli/ 可獨立發佈）
加新 cross-DB 方言normalize + emit + tables 三個檔加方言 case是
加新 GHA inputaction.yml + github-action.js flag 對照是
UI 加新 tab（plugin 動態）plugin 的 ui.tabs否
UI 加新 tab（內建）index.html + modules/foo.js + app.js init是

📝 一句話總結：日常 90% 的擴充需求用 plugin (sandboxed) 都能達到；要新 DB type 用 plugin 的 adapter capability；只有要動付款 / scope / permission / cross-DB 方言這種「跨多個元件」的擴充才需要 fork repo。
