🚀 啟動三件元件

① License Server

cd F:\匯出資料庫的bat\license-server
npm install         # 第一次
npm start
# License server listening on http://localhost:4000
# Admin UI:  http://localhost:4000/admin/

② DB Migrator (Node)

cd F:\匯出資料庫的bat\node-express
npm install         # 第一次
$env:LICENSE_MODE = "online"
$env:LICENSE_SERVER_URL = "http://localhost:4000"
npm start
# DB migrator listening on http://localhost:3000

③ DB Migrator (.NET)

cd F:\匯出資料庫的bat\dotnet8
dotnet restore      # 第一次
$env:LICENSE_MODE = "online"
$env:LICENSE_SERVER_URL = "http://localhost:4000"
dotnet run
# Now listening on: http://localhost:3001

停止：在對應 PowerShell 視窗按 Ctrl+C。

🧑‍💼 Admin 常用任務

建立新使用者

cd F:\匯出資料庫的bat\license-server

# 試用 (7 天 / 1 台)
node admin-cli.js create-user --email a@b.com --password trial1234

# Basic (1 台 / 到 2027-12-31)
node admin-cli.js create-user --email a@b.com --password mypass1234 --plan basic --expires 2027-12-31

# Team (5 台 / 到 2027-12-31)
node admin-cli.js create-user --email team@b.com --password mypass1234 --plan team --expires 2027-12-31

列出 / 查詢

node admin-cli.js list-users               # 所有使用者一覽
node admin-cli.js list-sessions             # 目前在線
node admin-cli.js list-sessions --email a@b.com   # 特定使用者的 session
node admin-cli.js list-events --limit 100  # 最近事件
node admin-cli.js list-events --email a@b.com

修改 plan / 延長期限

node admin-cli.js set-plan --email a@b.com --plan team --devices 5 --expires 2028-12-31

強制踢出登入

node admin-cli.js kick-all --email a@b.com

重新給試用

node admin-cli.js reset-trial --email a@b.com

撤銷（停用）

node admin-cli.js revoke --email a@b.com   # expires=now + 踢所有 session

刪除

node admin-cli.js delete-user --email a@b.com
Web 版 admin UI 在 http://localhost:4000/admin/，按鈕點點看就行。

📦 客戶第一次使用

  1. 客戶到你網站 / app 開啟 DB Migrator
  2. 右上角 🔑 圖示 → 「註冊試用」 → 填 email + password (≥ 8 字元)
  3. 收到驗證信，點連結啟用
  4. 回到 app，按「登入」
  5. banner 顯示「⏳ 試用中 — 剩 7 天」
  6. 使用流程：選 DB 卡片 → 填連線 → 連線測試 → 勾資料庫 → 匯出/匯入

試用版限制：

  • 只能 1 台同時使用
  • 多 DB 一次匯出被擋（只能勾 1 個）
  • 專案備份功能 disabled

💾 備份 license-server 資料

每天備份（手動）

# PowerShell
$date = Get-Date -Format "yyyy-MM-dd"
Copy-Item "F:\匯出資料庫的bat\license-server\license.db" `
          "F:\backups\license-$date.db"

每天備份（cron / 工作排程）

# Linux cron
0 3 * * * sqlite3 /var/lib/license-server/license.db ".backup /backups/license-$(date +\%F).db"

還原

# 停止 license server
# 取代 license.db 檔
# 重啟 license server
SQLite 用 WAL 模式 — 備份時還會有 license.db-wal、license.db-shm。最安全是 server 停掉後再 cp。

🌐 部署到 VPS（推薦 Caddy + systemd）

  1. VPS 裝 Node.js 18+、git、Caddy
  2. git clone 整個專案到 /opt/license-server
  3. 進去 npm install --production
  4. 建 systemd unit：/etc/systemd/system/license-server.service 
    [Unit]
Description=DB Migrator License Server
After=network.target

[Service]
WorkingDirectory=/opt/license-server
ExecStart=/usr/bin/node server.js
Restart=on-failure
Environment=PORT=4000
Environment=LICENSE_DB=/var/lib/license-server/license.db
Environment=PUBLIC_BASE_URL=https://license.your-domain.com
Environment=SMTP_HOST=smtp.sendgrid.net SMTP_PORT=587
Environment=SMTP_USER=apikey SMTP_PASS=YOUR_KEY SMTP_FROM=no-reply@your-domain.com

[Install]
WantedBy=multi-user.target
  5. 啟動：systemctl enable --now license-server
  6. Caddy 設反向代理 + 自動 HTTPS： 
    # /etc/caddy/Caddyfile
license.your-domain.com {
  reverse_proxy localhost:4000
}
  7. 客戶端的 LICENSE_SERVER_URL 改成 https://license.your-domain.com

🔁 更新部署

cd /opt/license-server
git pull
npm install --production
systemctl restart license-server
Schema 變動會在啟動時自動 migrate（db.js 的 addColumnIfMissing），不會弄壞舊資料。但仍建議升級前備份。

🐞 疑難排解

客戶說「無法登入」

檢查怎麼看怎麼修
License server 是否在跑curl https://license.your-domain.com/api/health沒回就重啟服務
客戶的 LICENSE_SERVER_URL 對不對看他 PowerShell echo $env:LICENSE_SERVER_URL跟他講正確 URL
帳號是否存在node admin-cli.js list-users | grep email不在就建
email 是否已驗證list-users 看 email_verified手動設 1 或重寄驗證信
是否被 IP 白名單擋list-events --email ... --limit 20 看「login_blocked」清空 ip_whitelist 或加新 IP
plan 是否過期list-users 看 expires_atset-plan --expires 延長
是否被踢看「kicked」事件kick-all 重置或叫客戶重新登入

客戶說「IP 一直變被踢」

常見場景：

  • 使用者用手機熱點 / 跨 WiFi → IP 真的會變
  • 公司用 NAT 出口 → IP 偶爾輪替
  • 客戶端跑在 docker / 容器 → 看到的 IP 不是真實 IP

解法：

  • 把 user 的 max_devices 加大（例如 3）→ 容忍 IP 短時間 churn
  • 給該用戶設 IP whitelist（範圍 CIDR）→ 在範圍內的 IP 換不會被踢（注意：目前 IP 變動還是會踢，這個 whitelist 只是限定哪些 IP 可以用，後續可改）
  • 請客戶找穩定 IP 環境

License server 噴錯 / 503

  • 看 journalctl -u license-server -n 200
  • SQLite lock 衝突：通常 WAL 模式不會有，但若多進程同寫會。檢查是否同時跑兩個 server.js
  • Disk full：df -h

Email 發不出去

  • SMTP 變數有沒有設？sender domain 是否在 SPF / DKIM 通過？
  • 用 swaks 從伺服器 manual 測 SMTP
  • 退而求其次：dev mode 印 console，從 log 撈連結手動給

📋 月維護清單

  • 檢查 license.db 大小，超過 100MB 跑 VACUUM
  • 清掉超過 90 天的 event_log（手動 SQL：DELETE FROM event_log WHERE at < date('now', '-90 days')）
  • 巡 license-server log，看有沒有重複的 login_blocked / kicked 案例（可能是某客戶網路有問題，主動聯繫）
  • SSL 憑證是否快過期（Caddy 自動續，但有時候會壞）
  • 備份檔輪替 — 例：保留最近 30 天

🔐 安全檢查清單（季度）

  • npm / dotnet 套件是否有 CVE：npm audit / dotnet list package --vulnerable
  • SMTP / Stripe / DB 密碼是否輪替？
  • Admin 帳號密碼是否強？
  • 有沒有不該有的 firewall 開放 port？
  • nginx / Caddy 是否最新版？

🆘 緊急 — 大規模誤踢 / 全部使用者被擋

  1. 第一時間：開 LICENSE_MODE=disabled 在客戶端臨時放行（如果你能控制客戶端 env）
  2. License server 端：找出 root cause（看 events / 看 logs）
  3. 修正後：取消 disabled，正常運作
  4. 事後：對受影響的客戶 reset_trial 補償，或在 license server 給 free_until 一週
