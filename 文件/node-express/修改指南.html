✏️ 修改指南 - DB Migrator (Node.js 版)

總覽 本版首頁 操作手冊 Function 對照 UI 解析 修改指南

這份指南列出常見的修改情境，每個情境告訴你 「動哪個檔」、「動哪一段」、「怎麼動」。所有路徑相對於 F:\匯出資料庫的bat\node-express\。

🟢 場景 1：換掉預設 port（不再用 3000）

📁 server.js 第 11 行
const PORT = process.env.PORT || 3000;
const PORT = process.env.PORT || 8080;  // 改成你要的

或不改 code，啟動時用環境變數：

set PORT=8080
npm start

🟢 場景 2：放大上傳檔大小限制（目前 1GB）

📁 routes/import.js 第 11 行
const upload = multer({
  dest: path.join(TMP_DIR, 'uploads'),
  limits: { fileSize: 1024 * 1024 * 1024 }, // 1GB
  limits: { fileSize: 5 * 1024 * 1024 * 1024 }, // 5GB
});
⚠️ 同時要注意：Node 預設 buffer 與 server 記憶體；超過幾 GB 建議改成串流寫入。

🟢 場景 3：把進度查詢輪詢頻率從 0.8 秒改成 0.3 秒

📁 public/app.js 第 173 行
await new Promise((r) => setTimeout(r, 800));
await new Promise((r) => setTimeout(r, 300));
💡 頻率太高會增加 server 負擔；太低會讓使用者覺得卡。建議 300–1000 ms。

🟢 場景 7：自動清理過期暫存檔

📁 server.js 在最末加排程
const os = require('os');

// 每 1 小時清理超過 24 小時的 export 暫存
setInterval(() => {
  const cutoff = Date.now() - 24 * 60 * 60 * 1000;
  for (const entry of fs.readdirSync(TMP_DIR)) {
    const p = path.join(TMP_DIR, entry);
    try {
      if (fs.statSync(p).mtimeMs < cutoff) fs.rmSync(p, { recursive: true, force: true });
    } catch {}
  }
}, 60 * 60 * 1000);

🟢 場景 8：加上 Basic Auth 防護

最簡單的方式：用 express-basic-auth 套件。

npm install express-basic-auth
📁 server.js 在路由之前加
const basicAuth = require('express-basic-auth');
app.use(basicAuth({
  users: { 'admin': 'changeme' },
  challenge: true,
}));
⚠️ 一定要搭配 HTTPS，否則密碼會在網路上以 base64 明文傳輸。

🟢 場景 9：在資料表清單顯示「實際筆數」而非估計值

📁 adapters/mysql.js 第 28 行 listTables

目前用 TABLE_ROWS 是估計值。要拿準確值得另跑 COUNT(*)，但會很慢：

async function listTables(conn) {
  const c = await mysqlPromise.createConnection(buildConnConfig(conn));
  try {
    const [rows] = await c.query(
      'SELECT TABLE_NAME AS name FROM information_schema.TABLES WHERE TABLE_SCHEMA = ? ORDER BY TABLE_NAME',
      [conn.database]
    );
    // 對每個表跑 COUNT(*) -- 大表會非常慢
    for (const r of rows) {
      const [[{ n }]] = await c.query(`SELECT COUNT(*) AS n FROM \`${r.name}\``);
      r.rowEstimate = n;
    }
    return rows;
  } finally { await c.end(); }
}
⚠️ 大型 DB 上跑 COUNT(*) 對每張表是高成本。建議只在使用者點「重新計算」按鈕才跑。

🟢 場景 10：把 dump 加上 gzip 壓縮

📁 adapters/mysql.js（其他 adapter 同理）

把 fs.createWriteStream 串到 zlib.createGzip()：

const zlib = require('zlib');

// 在 dump() 內：
const stream = fs.createWriteStream(outFilePath, { encoding: 'utf8' });
const gzip = zlib.createGzip();
const fileStream = fs.createWriteStream(outFilePath + '.gz');
gzip.pipe(fileStream);
const stream = gzip; // 後續寫到 stream 都會自動壓縮
💡 同時要改 export.js 的 downloadUrl 副檔名與 Content-Type。

📋 修改後檢核清單

  1. 修改後存檔，在 npm start 視窗按 Ctrl+C 重新啟動
  2. 用瀏覽器無痕模式打開（避免快取）
  3. F12 開 DevTools 看 Network 與 Console 有沒有錯誤
  4. 每改一個 adapter 要四種 DB 都測過（如果你有測試環境）
  5. 修改 UI 要在不同視窗寬度下測（建議 1280px、768px）
