專案概觀

這是用 .NET 8 / ASP.NET Core Web API 寫成的網頁工具，功能與 node-express 版完全相同（同 API、同 UI），只是技術 stack 換成 C#。
適合需要與既有 .NET 環境整合、或單一執行檔（self-contained publish）部署的情境。

啟動指令： 
cd F:\匯出資料庫的bat\dotnet8
dotnet restore
dotnet run        # 服務在 http://localhost:3001
或用 Visual Studio / Rider 開 DbMigrator.sln 然後 F5 執行。

系統運作流程

步驟使用者動作背後執行
1選擇 DB 類型前端 app.js 設定 state.type
2填連線資訊並按「連線測試」POST /api/connection/test → ConnectionController.Test → adapter.TestConnectionAsync
3測試成功後自動拉資料表清單POST /api/connection/tables → ConnectionController.Tables → adapter.ListTablesAsync
4a按「開始匯出」POST /api/export → 建 job → Task.Run 背景跑 adapter.DumpAsync
5a前端每 0.8 秒輪詢進度GET /api/jobs/{id} → 回 Job 物件
6a完成後點下載連結GET /api/export/{id}/file → PhysicalFile() 串流送回
4b選 SQL 檔按「檢查內容」POST /api/import/inspect → 解析 dump 並比對
5b按「執行匯入」POST /api/import/run → adapter.RestoreAsync

DI / 依賴注入

在 Program.cs 註冊兩個 singleton：

builder.Services.AddSingleton<JobService>();
builder.Services.AddSingleton<AdapterRegistry>();
builder.Services.AddControllers();

Controllers 透過建構式注入這兩個服務，全 process 共用同一份 job 狀態與 adapter 表。

已知限制

與 node-express 版完全相同：
  • ❌ 外鍵約束（CREATE TABLE 內不會包含）
  • ⚠️ 次要索引（SQLite 有，其他無）
  • ❌ Triggers / Stored procedures / Functions / Views
  • ❌ 沒有 auth — 不要直接放上公網
  • ⚠️ job 存記憶體，process 重啟後狀態清空（要持久化請改用 SQLite 或 Redis）
