DB Migrator 文件

瀏覽器操作的資料庫匯出 / 匯入工具。支援 MySQL、PostgreSQL、SQL Server、SQLite、Supabase，純 driver 實作，不需安裝任何 DB CLI。

系統需求 & 安裝

版本需要
Node.js 版NodeNode.js 18 以上
.NET 8 版.NET.NET 8 SDK

兩個版本功能完全一樣，前端 UI 也一樣，差別只在後端語言。

Node.js 版

cd F:\匯出資料庫的bat\node-express
npm install
首次安裝 better-sqlite3 會做 native build。Windows 需要 Visual Studio Build Tools；不打算用 SQLite 可從 package.json 拿掉那一行。

.NET 8 版

cd F:\匯出資料庫的bat\dotnet8
dotnet restore

或直接用 Visual Studio / Rider 開 DbMigrator.sln，IDE 會自動 restore。

啟動

Node.js 版port 3000

cd F:\匯出資料庫的bat\node-express
npm start
# DB migrator listening on http://localhost:3000

.NET 8 版port 3001

cd F:\匯出資料庫的bat\dotnet8
dotnet run
# Now listening on: http://localhost:3001

停止：那個 PowerShell 視窗按 Ctrl+C。

UI 流程概覽

1. 選擇資料庫類型卡片（MySQL / PostgreSQL / SQL Server / SQLite / Supabase）
        ↓
2. 連線設定（Host + Port + User + Password；Database 不用填）
        ↓
   按「連線測試」
        ↓

連線 SQL Server (含 SQLEXPRESS)

預先準備：開啟 TCP/IP（重要）

SQL Express 預設沒開 TCP/IP，要先開：

  1. 開 SQL Server Configuration Manager
  2. SQL Server Network Configuration → Protocols for SQLEXPRESS → 把 TCP/IP 改成 Enabled
  3. SQL Server Services → 重啟 SQL Server (SQLEXPRESS)，確認 SQL Server Browser 是 Running（如果用 instance 名稱連線）
  4. Windows 防火牆放行 1433（內網連才需要；本機連跳過）
SSMS 預設用 Shared Memory 連本機，不需要 TCP/IP；我們的工具走 tedious driver，只支援 TCP/IP。所以 SSMS 連得到 ≠ 本工具連得到。

Server 欄位格式

格式範例何時用
HOST192.168.1.50預設 instance + 預設 port
HOST,PORT192.168.1.50,1433預設 instance + 自訂 port
HOST\INSTANCEDESKTOP-PNPEK4O\SQLEXPRESS命名 instance（靠 SQL Browser 解析 port）
HOST\INSTANCE,PORTDESKTOP-PNPEK4O\SQLEXPRESS,1434命名 instance + 自訂 port

連線 SQLite

SQLite 檔案路徑C:\data\app.db、F:\projects\test.sqlite
路徑必須是跑 web app 那台機器上看得到的本機路徑。沒辦法直接匯入瀏覽器端的 .db 檔。

連線 Supabase

Supabase 底層是 PostgreSQL + 強制 TLS。本工具的 Supabase 卡片自動：路由到 postgres adapter、強制 SSL、預設值適合 Supabase 工作流。

取得連線資訊

到 Supabase Dashboard → Project Settings → Database：

Hostdb.<project-ref>.supabase.co
Port5432（Direct connection）
Databasepostgres
Userpostgres
Password你在 Supabase 設的 DB password
DB 密碼是單獨設定的（不是登入 Supabase 的密碼）。在 Database 那頁有「Reset database password」按鈕，重設一次就會給你看，存好。
不要用 Pooler endpoint（aws-0-*.pooler.supabase.com:6543）跑 dump / restore，會把 prepared statements 搞亂。要用 Direct connection。

IPv6 注意

免費方案的 Direct 連線是 IPv6-only。你的網路沒 IPv6 連不上的話，要去 dashboard 開「IPv4 add-on」（要錢）或想其他辦法。

匯出操作

  1. 連線測試成功後，2.5 區塊勾選要匯的 DB
  2. 切到「匯出」分頁（預設就在這）
  3. 選擇匯出範圍（單 DB 才有此選項）：
    • 全部匯出：整個 DB 一個 SQL 檔
    • 選擇資料表：勾選要的 table
  4. 進階選項（兩個 checkbox 二擇一或都不勾）：
    • 只匯出結構 (no data)：只有 CREATE TABLE
    • 只匯出資料 (no schema)：只有 INSERT
  5. 按「開始匯出」
  6. 黑底 log 區會跑進度，完成後出現「下載檔案」連結

檔案放在哪？

  • Node：F:\匯出資料庫的bat\node-express\tmp\<jobId>\
  • .NET：F:\匯出資料庫的bat\dotnet8\bin\Debug\net8.0\tmp\<jobId>\

目前不會自動清，定期手動清掉。

匯入操作

  1. 同樣先選 DB 類型 → 填連線 → 連線測試
  2. 2.5 區塊只勾一個目標 DB
  3. 切到「匯入」分頁
  4. 選 SQL 檔（自己之前匯出的或別處給你的）
  5. 按「檢查內容」
  6. 出現對照表：
    • 綠色「不存在（新建）」→ 安全
    • 黃色「已存在（將覆寫）」→ 注意，會被 DROP+CREATE 覆寫
  7. 確認後按「執行匯入」
目前限制：對照表的 checkbox 還沒真的篩選 table，按下執行匯入會跑整份檔。要部分匯入請先用文字編輯器把不要的部分刪掉，或在源頭匯出時就只勾要的 table。

已儲存連線（最近使用）

連線測試成功會自動把該組設定（不含 database）存到瀏覽器 localStorage，下次點同樣的卡片自動帶最近成功的那組。連線設定區頂端會出現「最近使用」下拉，可以存最多 10 組不同連線：

最近使用：[ sa@DESKTOP-PNPEK4O\SQLEXPRESS  ▼ ]   [刪除這筆]
         [ root@10.0.0.5                  ]
         [ postgres@db.xxx.supabase.co 🪟  ]
帳密以明文存於瀏覽器 localStorage。共用電腦或重要環境記得手動清掉：F12 console → localStorage.removeItem('dbmigrator.connections.v1')

疑難排解

連線測試失敗

錯誤訊息原因解法
ECONNREFUSEDDB 沒開、port 錯確認 DB service 在跑、port 對
ETIMEDOUT防火牆擋、安全群組沒放行開放對應 port、加 IP 白名單
MySQL Access denied帳密錯重填
PG password authentication failed帳密錯重填
MSSQL Login failed帳密錯 / Mixed Mode 沒開確認 SQL Server 驗證模式
MSSQL Could not find the requested instanceSQL Browser 沒跑 / TCP 沒開看上面 SQL Server 預先準備
SQLite unable to open database file路徑不存在 / 沒權限確認檔案存在或路徑可寫
Supabase SSL/TLS required用了 PostgreSQL 卡片連 Supabase改用 Supabase 卡片（會自動啟用 SSL）

瀏覽器 console 顯示「失敗：undefined」

表示 server 端沒回 error 欄位（通常是請求 body 反序列化失敗）。已修復，但若還碰到：

  1. F12 → Network → 點失敗那個 request → Response 看實際內容
  2. Server 端 console 會印 [connection/test] failed: 詳細訊息

找不到「？」按鈕

清快取重整：Ctrl+F5。要把「已看過指引」記錄清掉重跑：

localStorage.removeItem('dbmigrator.tourSeen.v1')

關鍵概念

  • Adapter 介面：每種 DB 實作 5 個方法（testConnection / listTables / dump / restore / parseTableNamesFromDump）
  • Job：匯出 / 匯入是長時間任務，背景跑、回 jobId、前端 polling /api/jobs/:id
  • Tmp dir：匯出檔放 tmp/<jobId>/，多 DB 包成 dumps.zip；上傳的匯入檔放 tmp/uploads/（用完即刪）
  • Streaming：dump 用串流（SELECT * → DataReader / QueryStream），不會把整張表 load 到記憶體

加新 DB

Node 版

  1. npm install <driver-package>
  2. 建 adapters/yyy.js，照其他 adapter 的結構實作 5 個方法
  3. 到 adapters/index.js 註冊：const yyy = require('./yyy'); adapters.yyy = yyy;

.NET 版

  1. <PackageReference Include="..."> 加 NuGet
  2. 建 Adapters/YyyAdapter.cs 實作 IDatabaseAdapter
  3. 到 AdapterRegistry 建構式註冊：["yyy"] = new YyyAdapter()

前端

  • 到 public/index.html 加新卡片：<button class="card" data-type="yyy" data-port="...">...</button>
  • 到 app.js 的 TYPE_DEFAULTS 跟 HOST_HINTS 加對應 entry

已知限制

項目純 driver 版（本工具）原生 dump 工具（mysqldump/pg_dump/sqlcmd）
表結構（基本）✅ 欄位 / 型別 / PK / 預設值 / nullable / IDENTITY✅
資料✅ 串流批次 INSERT✅
外鍵約束❌ 不在 CREATE TABLE 內✅
次要索引⚠️ SQLite 有，其他無✅
Triggers❌✅
Stored procedures / functions❌✅
Views❌（被當成 BASE TABLE 跳過）✅
Sequences (PG)❌✅
Events (MySQL)❌✅

一般 application DB 用前兩項就夠。要做 enterprise 級的完整匯出再加上面這些 SQL 查詢就好（PG 的 pg_get_constraintdef、MSSQL 的 sys.foreign_keys 等）。

其他

  • 匯入時 UI 上的 table 勾選 還沒真的篩選，會跑整份檔
  • 密碼明文存於 localStorage
  • 沒有 auth / rate limit / audit log — 別直接上公網
  • 匯出 tmp 檔不會自動清

安全性

本工具沒有 auth。任何能連到這個 web app 的人都能 dump / restore 任何他能連到的 DB。絕對不要直接上公網。

外露前最少要做：

  • HTTPS（Caddy / nginx 反向代理或 Cloudflare Tunnel）
  • 登入機制（最少 basic auth）
  • Rate limit（防止暴力測 DB 帳密）
  • Audit log（誰在什麼時候連到什麼 DB、做了什麼）
  • 限制可連的目標 DB（白名單 host）

已做的防護

  • 所有 DB 操作走 driver，沒有用 shell 拼接，無 command injection
  • SQL 操作用 parameterized query（adapter 內部）
  • 上傳檔限制 1GB，存於 tmp/uploads，匯入完自動刪
  • SQL Server / PostgreSQL / Supabase 都驗證 server 但不驗 cert（為了 Supabase managed cert 方便；正式環境應該 bundle CA）
